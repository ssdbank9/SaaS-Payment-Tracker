What you need

Gather these before you start

  • An Oracle Cloud account, signed in at cloud.oracle.com. You already have one; it also runs an older 1 OCPU / 6 GB VM for another project.
  • A DuckDNS account: duckdns.org, sign in with Google. No card, no email confirmation.
  • An admin passcode you choose: at least 8 characters, 12 or more is better. You will type it once per device, and a device stays signed in for 90 days.
  • A Windows PC with PowerShell (built in) to connect to the server, and your phone for the first sign-in.
  • Optional, for later: a Google AI Studio key (screenshot reading) and a Gmail app password (automatic reminder emails).

Words you will meet

A VM (instance) is a computer you rent in Oracle's data centre. SSH is the secure way to type commands on it from your PC. DNS turns wasooli.duckdns.org into the VM's address. A security list is Oracle's firewall in front of the VM.

Commands in this guide are shown in dark boxes with a Copy button. Parts highlighted in yellow are placeholders you replace with your own value. Nothing else in a box needs changing.

Create the Oracle instance

Oracle Cloud console, in a browser (done 22 Sep 2026, about 16:45 PKT)

Menu (three lines, top left):

Compute›Instances›Create instance

Fill the form top to bottom. Leave anything not listed here at its default, including everything under Advanced options.

Name
wasooli (any name; the VM you built was left as instance-20260922-1643)
Placement
leave the availability domain Oracle picks
Image
Change image → Canonical Ubuntu → 24.04. With the Ampere shape below Oracle uses the aarch64 build; "aarch64" or "arm64" next to the image is correct.
Shape
Change shape → Ampere → VM.Standard.A1.Flex → 1 OCPU, 6 GB memory. Look for the "Always Free-eligible" label.
Networking
Create new virtual cloud network (yours became vcn-20260922-1643 with subnet subnet-20260922-1643). Keep Assign a public IPv4 address selected.
SSH keys
Generate a key pair for me → Save private key. A file such as ssh-key-2026-09-22.key lands in your Downloads folder. Keep it: it is the only key to the server and Oracle cannot give it to you again.
Boot volume
default (about 47 GB), free

Click Create. The instance shows Provisioning for a minute or two, then Running.

Always Free allowance. The free Ampere quota is 4 OCPUs and 24 GB in total for the whole tenancy, shared by every A1 VM you have. Your other project's VM uses 1 / 6 and Wasooli uses 1 / 6, leaving 2 / 12 spare. Nothing is charged for Always Free resources.
"Out of capacity" / "Out of host capacity"? Free Ampere servers are popular and a region sometimes has none spare. It is not an account problem. In order: click Create again in 10–30 minutes and again a few hours later; under Placement try another availability domain if your region has more than one; keep the 1 / 6 size (smaller requests succeed more often). You did not hit this on 22 September.

Copy the public IP

The instance page

On the instance page, under Instance access (or in the Instance information tab), find Public IP address and press Copy. Yours is:

public IP
141.145.157.7

Paste it into a note. You use it in steps 4 and 5. It does not change on a reboot; it only changes if you stop the instance and it was created with an ephemeral address, or if you terminate and recreate the VM.

Open ports 80 and 443 in Oracle's firewall

Oracle Cloud console, starting from the instance page

Oracle blocks web traffic to a new VM at the cloud level. You open two doors: 80 (needed to get the HTTPS certificate) and 443 (HTTPS itself). Port 22 (SSH) is already open.

instance page›Attached VNICs›subnet link (subnet-20260922-1643)›Security Lists›Default Security List for vcn-20260922-1643›Add Ingress Rules

Fill the first rule:

Stateless
leave unticked
Source type
CIDR
Source CIDR
0.0.0.0/0 (anyone on the internet)
IP protocol
TCP
Source port range
leave empty
Destination port range
80
Description
HTTP (optional)

Click + Another Ingress Rule, repeat exactly with destination port 443 (description HTTPS), then Add Ingress Rules.

There are two firewalls. This one belongs to Oracle's network and only you can open it in the console. The second is inside the VM; the installer in step 6 opens that one itself. If either stays closed the site times out.
4

DuckDNS: two names pointing at the VM

duckdns.org, signed in with Google

You need two free names on the same IP: one for you to sign in on, one that goes in the links you send to subscribers (so a link never shows where the sign-in page is).

Admin
wasooli.duckdns.org
Links
pay-up.duckdns.org
  1. Under domains, type wasooli and click add domain. Repeat with pay-up.
  2. Replace the auto-filled IP. DuckDNS fills the current ip box with the address of the computer you are sitting at (your home or office connection), not the VM. Delete it, paste 141.145.157.7, and click update ip on each row. This caught you the first time: the name pointed at home and the site did not load until it was changed.

Check from PowerShell on the PC (the replies themselves may time out; only the IP in the first line matters):

ping wasooli.duckdns.org
ping pay-up.duckdns.org

Or open dnschecker.org, type the name and look for 141.145.157.7. DuckDNS is usually live within a minute or two.

What happened to wasool.duckdns.org. The first install used wasool.duckdns.org. On 23 September you created the two names above and deleted the old one. From that moment the site was unreachable until the installer was re-run with the new names (step 6). If you ever rename again: add the new name first, re-run the installer, then delete the old one.

Sign in to DuckDNS once in a while; a name that is never touched can expire after a long time.

5

Connect from Windows

PowerShell on the PC

Press Win+X and choose Terminal (or Windows PowerShell). The prompt looks like PS C:\Users\Aly Jafferani>. Paste this line and press Enter. The quotes matter because your Windows user folder has a space in its name:

PowerShell
ssh -i "$env:USERPROFILE\Downloads\ssh-key-2026-09-22.key" ubuntu@141.145.157.7

Replace the file name only if your key downloaded under a different name (look in Downloads). The user name is always ubuntu.

The fingerprint question

The first time it asks Are you sure you want to continue connecting (yes/no/[fingerprint])? Type yes in full and press Enter. Typing just y is rejected and asks again.

If it says "UNPROTECTED PRIVATE KEY FILE" / "Permissions are too open"

Windows gives a downloaded file broad permissions and SSH refuses to use it. This happened on your first attempt. Run these two lines, then the ssh line again:

icacls "$env:USERPROFILE\Downloads\ssh-key-2026-09-22.key" /inheritance:r
icacls "$env:USERPROFILE\Downloads\ssh-key-2026-09-22.key" /grant:r "${env:USERNAME}:R"

What success looks like

A block of Ubuntu welcome text, then a prompt that ends in $:

you are on the VM when you see this
ubuntu@instance-20260922-1643:~$
Paste server commands only at the ubuntu prompt. If the connection drops (you saw client_loop: send disconnect: Connection reset) you are back at the PS C:\…> prompt of your own PC. A server command pasted there does something else or fails: the installer's curl line produced an Invoke-WebRequest error because PowerShell has its own curl. Reconnect with the ssh line first, wait for ubuntu@…:~$, then paste.

To leave the server later, type exit.

6

Run the installer

At the ubuntu prompt on the VM; 3–5 minutes

One line installs everything: Python, git, Caddy (HTTPS), the Wasooli code, the systemd services and timers, the firewall rules, and the settings file. Replace the passcode; keep both domain names as they are:

on the VM · current command with both names
curl -fsSL https://raw.githubusercontent.com/ssdbank9/SaaS-Payment-Tracker/main/deploy/setup.sh | sudo DOMAIN=wasooli.duckdns.org LINK_DOMAIN=pay-up.duckdns.org ADMIN_PASSCODE='choose-a-long-passcode' bash

Keep the single quotes around the passcode. Avoid a single quote inside it. Nothing is echoed while it runs; you see green ==> lines as each part finishes:

==> Installing packages (python3-venv, git, Caddy)
==> Fetching Wasooli into /opt/payments-tracker
==> Writing /etc/payments-tracker.env
==> Installing systemd units
==> Configuring Caddy for wasooli.duckdns.org, pay-up.duckdns.org
==> Opening ports 80 and 443 in iptables
==> Checking the service
gunicorn answers on 127.0.0.1:8080: {"app":"wasooli","ok":true,...}

Wasooli is installed.

  Sign in here:   https://wasooli.duckdns.org/x/Xy7…24 random characters…
                  Bookmark this. It is the only place the sign-in form exists; the plain
                  https://wasooli.duckdns.org shows strangers a blank page (also in Settings -> Security).
  Passcode:       the ADMIN_PASSCODE you set (kept in /etc/payments-tracker.env)
  Links:          https://pay-up.duckdns.org/c/<token>  (separate address, never shows where you sign in)
  Data:           /var/lib/payments-tracker (SQLite + receipts; nightly backups in /var/lib/payments-tracker/backups)
  Updates:        every 5 minutes the VM checks GitHub (main) and restarts on a new commit
  Emails:         payments-tracker-notify.timer runs daily at 09:00 PKT once SMTP is set in Settings -> Mail
  Logs:           journalctl -u payments-tracker -f      /      journalctl -u caddy -f

The private sign-in address

The line Sign in here is the only address with a login form. Select it in the terminal, copy it, and bookmark it on the PC and on the phone (send it to yourself by email or WhatsApp). Anyone who only knows wasooli.duckdns.org sees a blank page with the mark and "Nothing to see here." That is by design, not a fault. The address is also shown later in Settings → Security.

Certificate wait

Caddy asks Let's Encrypt for certificates for both names the moment it starts. With DNS already pointing at the VM this takes under a minute. If the installer ends with currently resolves to: nothing yet, DNS has not spread: wait, then run the same line again.

Running it again

The installer is safe to repeat. Every value you leave off the line is kept from the previous run (passcode, secret key, sign-in path, API keys), so:

  • To change only the passcode: the same line with a new ADMIN_PASSCODE='…'.
  • To change or add a domain: the same line with the new DOMAIN= / LINK_DOMAIN=; the previous admin domain is kept as a redirect unless you add OLD_DOMAIN= (empty) to drop it.
  • To repair after something odd: the same line with nothing but the two domains. It never asks questions when run this way.

The very first install on 22 September used one name only: DOMAIN=wasool.duckdns.org. The re-run on 23 September switched to the two names above.

First sign-in and Add to home screen

Your phone

  1. Open the bookmarked https://wasooli.duckdns.org/x/… address. The padlock shows; the page has the green Wasooli tile and a passcode box.
  2. Type the passcode once. The device stays signed in for 90 days (renewed on every visit) and is remembered as a known device, so from now on even the plain wasooli.duckdns.org takes this phone to the sign-in page.
  3. A fresh server shows sample users. Replace them with your data: Settings → Your data → Import everything (JSON) with an export from the old copy, or just edit the list.
  4. Add to home screen. Android Chrome: menu (three dots) → Add to Home screen → Add. iPhone Safari: Share → Add to Home Screen. The icon is the green Wasooli tile, named "Wasooli", and it opens full screen like an app.
Do the same on the PC browser: open the sign-in bookmark, sign in once. If you ever see Too many attempts from this device, that is the per-device lockout (8 wrong passcodes in 15 minutes); wait 15 minutes. It never affects a device that is already signed in.

Settings to fill in on the site

Header → Settings; press Save after each block

Packages

C at Rs 4,200 monthly is preset. Give C Max its monthly price (it is blank until you do; upgrades from a link use this price) and G its yearly price. Add a package when a new product launches.

Billing cycle

Starts on day 24; reminder day 20; reply-by day 23; proration basis fixed 30-day month; default rate 280 PKR per USD. These are already set; check them once.

WhatsApp opens in

Set to Regular so links do not open WhatsApp Business. If the phone still picks Business: Android Settings → Apps → WhatsApp Business → Open by default → Clear defaults.

AI reading (screenshots)

Provider Google Gemini. Paste a key from aistudio.google.com, press Load models (the newest Flash-Lite is preselected), Save. The key stays on the server.

Mail (optional)

For automatic reminder emails: host smtp.gmail.com, port 587, your Gmail address, a Gmail app password (Google account → Security → 2-Step Verification → App passwords), from name Wasooli. Press Send test email to me. The daily job runs at 09:00 PKT.

Templates and How to pay

The three Queue stage messages (reminder, repeat, final note) and the "How to pay" line are editable. Placeholders such as {name}, {amount}, {link} are filled per user.

Security block. Settings → Security shows the sign-in address (Copy / Open / Regenerate), Sign out and Sign out everywhere (for a lost phone). The Public base URL field is locked to https://pay-up.duckdns.org because the link domain is set on the server.
9

Sending links and reading answers

Header → Queue, from the 20th of each month

  1. Open Queue. It shows today's stage from the date alone: reminder from the 20th, repeat to anyone silent from the 23rd, and the final note ("your account continues from the 24th") on the 24th.
  2. Each row has the finished message with the subscriber's private link on https://pay-up.duckdns.org/c/… and buttons: WhatsApp, Telegram (+ Copy), Email. Tap one, send, and tick Sent.
  3. The subscriber's page shows their first name, tier, amount and dates, and three big buttons: Continue, Upgrade to C Max (or Move back to C), Discontinue, plus a note box. Nothing else about the account is visible.
  4. Answers appear in the Queue and in the Reminder run / Final notice lists, and are applied once: Continue ticks Confirmed; Upgrade adds a tier change from the next cycle; Discontinue marks the user with a one-tap Confirm cancel.

If a subscriber's link says Link not active, open the Queue once on the site (that stores the link details), then Copy link again and send the fresh one.

With Mail set up (step 8), the server emails the day's stage itself at 09:00 PKT to everyone with an email address who has not had it this cycle, and ticks them as sent. WhatsApp and Telegram stay one tap by hand; there is no Meta API involved.

Keeping it running

Mostly nothing to do; commands for when you need them (run on the VM, step 5)

Automatic

  • Updates: every 5 minutes the VM checks GitHub. A change committed to main (for example from Claude Code) is live within 5 minutes; the version badge in the header (v26, v27, …) tells you.
  • Backups: every night at 03:15 a copy of the database is written to /var/lib/payments-tracker/backups/ (newest 30 kept) plus one archive of uploaded receipts.
  • Reminder emails: daily at 09:00 PKT, only once Mail is set up.
  • Certificates: Caddy renews them itself.

Now and then use Settings → Your data → Export everything (JSON) and keep the file in your cloud drive; it is the copy that is not on the VM.

Check that everything is up

sudo systemctl status payments-tracker caddy --no-pager

Both should read active (running). The three timers:

systemctl list-timers 'payments-tracker*' --no-pager

Recent log lines (lockouts show here as login: … locked):

sudo journalctl -u payments-tracker -n 50 --no-pager
sudo journalctl -u caddy -n 50 --no-pager

Without logging in, any browser can open https://wasooli.duckdns.org/healthz; it answers {"ok": true, "app": "wasooli", "version": "26", …}.

Change the passcode or a domain

Re-run the step 6 line with the new value; everything you leave out is kept:

curl -fsSL https://raw.githubusercontent.com/ssdbank9/SaaS-Payment-Tracker/main/deploy/setup.sh | sudo ADMIN_PASSCODE='new-passcode' bash

Devices already signed in stay signed in; use Sign out everywhere in Settings → Security if you want them out.

Rotate the sign-in address

Settings → Security → Regenerate. Copy the new address and update the bookmarks on the PC and phone before you sign out anywhere. The new value is kept in the database and wins over the settings file.

Restore a backup

ls -1t /var/lib/payments-tracker/backups/
sudo systemctl stop payments-tracker && sudo sh -c 'gunzip -c /var/lib/payments-tracker/backups/tracker-20260923-031500.sqlite3.gz > /var/lib/payments-tracker/tracker.sqlite3' && sudo chown payments-tracker:payments-tracker /var/lib/payments-tracker/tracker.sqlite3 && sudo systemctl start payments-tracker

Or, without the terminal: Settings → Your data → Import everything (JSON) with an export you kept.

Force an update right now

sudo /opt/payments-tracker/deploy/update.sh

If the VM's IP ever changes

Only after a stop/start with an ephemeral address, or a new VM. Sign in to DuckDNS, put the new IP in both rows (wasooli and pay-up), click update ip, then on the VM:

sudo systemctl restart caddy

Update the IP in your ssh line too. On a brand-new VM, repeat steps 3 to 6 and restore a backup or import your JSON export.

Changing the site itself

Open claude.ai/code, pick the repository ssdbank9/SaaS-Payment-Tracker, describe the change in plain words. Claude reads CLAUDE.md, makes and tests the change and commits it; the VM picks it up within 5 minutes. To undo, ask for "revert the last commit". The technical hand-off is docs/HANDOFF.md in the repository.
